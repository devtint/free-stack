Vercel

Push to GitHub and get a live site with a preview URL for every branch. This guide covers deploying, configuring and staying inside the Hobby plan.

What you get

Vercel builds your project from Git, serves static files from its global CDN and runs your server code as Vercel Functions. It detects most frameworks automatically, including Next.js, Vite, Astro, SvelteKit, Nuxt and plain static sites.

Hobby is for personal, non-commercial projectsVercel defines commercial use broadly: taking payments, showing ads, selling a product or being paid to build the site all count. Asking for donations does not. If a project starts earning, move it to Pro.

Deploy from GitHub

  1. Push your project to GitHubMake sure it builds locally with your normal build command first.
  2. Import itGo to vercel.com/new, connect GitHub and pick the repository. Hobby can only import repositories owned by your personal account, not by a GitHub organization.
  3. Check the settingsVercel picks the framework preset, build command and output folder. Set the Root Directory if the app lives in a subfolder of a monorepo.
  4. Add environment variablesAdd them now so the first build has them. You can change them later.
  5. DeployYou get a project.vercel.app URL in a minute or two. From now on every push deploys automatically.

Production and preview

Each push creates a deployment. Which environment it lands in depends on the branch:

EnvironmentCreated byURL
ProductionPushes to the production branch, usually mainYour project domain and custom domains
PreviewPushes to any other branch, and every pull requestA unique URL per deployment, plus one per branch
DevelopmentYour machine, with vercel dev or your framework's dev serverlocalhost

Preview URLs are posted as a comment on the pull request, which makes review easy. By default, previews are protected by Vercel Authentication, so only people on your team can open them.

To undo a bad release, open Deployments, pick an earlier production deployment and choose Instant Rollback. No rebuild is needed.

The Vercel CLI

Terminal
npm install -g vercel

vercel login
vercel link              # connect this folder to a project
vercel                   # deploy a preview
vercel --prod            # deploy to production
vercel env pull .env.local   # download Development env vars
vercel logs your-deployment-url

The CLI uploads your local files, so it is handy for quick tests. For normal work, prefer pushing to Git so every deployment matches a commit.

Environment variables

  1. Add the variableProject, Settings, Environment Variables. Choose which environments get it: Production, Preview, Development or any mix.
  2. Mark secrets as sensitiveSensitive values cannot be read back from the dashboard after you save them.
  3. RedeployVariables are read at build time and at runtime of new deployments. Existing deployments keep the old values until you redeploy.
Public prefixes ship to the browserVariables starting with NEXT_PUBLIC_ (Next.js) or VITE_ (Vite) are compiled into client JavaScript. Only put publishable keys there, never secret keys.

Functions

Any server code, such as a Next.js route handler or a file in the api folder, becomes a Vercel Function. Functions run with Fluid compute, which reuses warm instances for concurrent requests, so cold starts are rarer and you pay for active CPU rather than idle waiting.

app/api/hello/route.ts
export async function GET(request: Request) {
  const { searchParams } = new URL(request.url)
  const name = searchParams.get('name') ?? 'world'
  return Response.json({ message: `Hello ${name}` })
}

Without a framework, export a fetch handler from a file in api/:

api/hello.ts
export default {
  fetch(request: Request) {
    return new Response('Hello from Vercel')
  },
}

Run work after responding

TypeScript
import { waitUntil } from '@vercel/functions'

export async function POST(request: Request) {
  const event = await request.json()
  waitUntil(saveToDatabase(event))   // keeps running after the response
  return new Response('ok')
}

Put functions near your database

Functions run in one region, Washington D.C. (iad1) by default. If your Supabase project is in, say, Frankfurt, change the function region in Project Settings, Functions to match. Every database round trip across an ocean adds around 100 ms.

Python and other runtimes

Vercel also runs Python (for example FastAPI or Flask), Go and Ruby functions, and container images. Long-lived processes such as a polling Telegram bot or a WebSocket server are a better fit for Render.

Cron jobs

Cron jobs call one of your function paths on a schedule. Define them in vercel.json:

vercel.json
{
  "crons": [
    { "path": "/api/daily-cleanup", "schedule": "0 3 * * *" }
  ]
}
Hobby crons run at most once a dayExpressions that run more often, such as every hour, fail the deployment. Timing is also loose: a job set for 03:00 can run any time between 03:00 and 03:59. For more frequent jobs, use GitHub Actions or cron-job.org.

Protect the route so strangers cannot trigger it. If you set a CRON_SECRET environment variable, Vercel sends it as a bearer token:

TypeScript
export async function GET(request: Request) {
  if (request.headers.get('authorization') !== `Bearer ${process.env.CRON_SECRET}`) {
    return new Response('Unauthorized', { status: 401 })
  }
  // do the job
  return new Response('done')
}

Custom domains

  1. Add the domainProject, Settings, Domains, Add. Add both example.com and www.example.com and choose which one redirects to the other.
  2. Create the DNS recordsVercel shows the exact records to add at your DNS provider: an A record for the apex domain and a CNAME for subdomains. Copy the values from the dashboard, since they can be specific to your project.
  3. Wait for verificationOnce DNS resolves, Vercel issues an HTTPS certificate automatically. This usually takes minutes, occasionally up to a few hours.

Using Cloudflare for DNS? Set the Vercel records to DNS only (grey cloud). See the Cloudflare guide for why.

Useful vercel.json settings

vercel.json
{
  "redirects": [
    { "source": "/blog/:slug", "destination": "/posts/:slug", "permanent": true }
  ],
  "headers": [
    {
      "source": "/(.*)",
      "headers": [{ "key": "X-Content-Type-Options", "value": "nosniff" }]
    }
  ],
  "cleanUrls": true
}

To skip builds for commits that do not touch your app, set an Ignored Build Step in Project Settings, Git. For example git diff --quiet HEAD^ HEAD ./apps/web skips the build when nothing in that folder changed.

Troubleshooting

Build works locally but fails on Vercel

Common causes: a missing environment variable, a file name whose case differs from the import (Linux is case sensitive), or a different Node.js version. Set the Node version in Project Settings, Build and Deployment, or with engines.node in package.json.

Environment variable is undefined

Check that it is enabled for the environment you deployed to, then redeploy. Variables do not change existing deployments. In the browser, only variables with the public prefix exist.

Function timed out

Hobby functions stop at 300 seconds. Move long work into a background job, or reply quickly and finish with waitUntil. Slow database calls are often a region mismatch.

404 on page refresh in a single-page app

Add a rewrite so all paths serve index.html: {"rewrites": [{"source": "/(.*)", "destination": "/"}]}.

Cannot import a repository from my GitHub organization

Hobby only connects repositories owned by your personal account. Move the repo to your account or use a Pro team.

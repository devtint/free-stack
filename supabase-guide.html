Supabase

Postgres, auth, file storage and realtime in one project. This guide takes you from an empty account to a secured table your app can read and write.

What you get

Every Supabase project is a dedicated Postgres database with a set of services in front of it: a REST API generated from your tables, an auth server, file storage, realtime messaging and Edge Functions. You talk to all of it through one client library and two API keys.

The free plan is generous for side projects and early products. The trade-offs to plan around are that projects pause after a week without activity, there are no automatic backups, and logs are kept for one day.

Create a project and get your keys

  1. Create the projectIn the dashboard choose New project. Pick the region closest to your users or to your backend host. The region cannot be changed later.
  2. Save the database passwordIt is shown once. Put it in a password manager. You only need it for direct Postgres connections.
  3. Copy the URL and keysOpen Project Settings, then API Keys. Copy the project URL, the publishable key and, if you have a backend, a secret key.

Supabase now issues two kinds of keys. Choosing the right one is the most important security decision you make.

KeyLooks likeUse it inWhat it can do
Publishablesb_publishable_...Browsers, mobile apps, CLIsRuns as anon or as the signed-in user. Limited by your RLS policies.
Secretsb_secret_...Servers, bots, cron jobs, Edge FunctionsRuns as service_role and bypasses RLS. Rejected if sent from a browser.
Legacy keys are being retiredOlder projects show anon and service_role keys that start with eyJ. They map to the publishable and secret keys and still work, but Supabase is deprecating them by the end of 2026. Create the new keys, switch your apps over, then disable the legacy ones in Settings, API Keys.

Environment variables

Use these names so it is obvious which values are safe in the browser. Anything with a public prefix such as NEXT_PUBLIC_ or VITE_ gets bundled into client code.

.env.local
# Browser safe
NEXT_PUBLIC_SUPABASE_URL=https://your-project.supabase.co
NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY=sb_publishable_xxx

# Server only. Never give this a public prefix.
SUPABASE_URL=https://your-project.supabase.co
SUPABASE_SECRET_KEY=sb_secret_xxx

Connect from your app

JavaScript or TypeScript

Terminal
npm install @supabase/supabase-js
lib/supabase.ts
import { createClient } from '@supabase/supabase-js'

export const supabase = createClient(
  process.env.NEXT_PUBLIC_SUPABASE_URL!,
  process.env.NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY!
)

If you use Next.js with server components or middleware, install @supabase/ssr as well. It stores the session in cookies so the server and browser see the same signed-in user. Follow the official Next.js quickstart for the exact helper files.

Python (backends and bots)

Terminal
pip install supabase
db.py
import os
from supabase import create_client

# Server side, so the secret key is fine here
supabase = create_client(os.environ["SUPABASE_URL"], os.environ["SUPABASE_SECRET_KEY"])

rows = supabase.table("notes").select("*").limit(10).execute()
print(rows.data)

Tables and Row Level Security

Tables in the public schema are reachable through the API. Row Level Security (RLS) decides which rows each request can see or change. With RLS on and no policies, the publishable key can do nothing, which is the safe default.

Rule of thumbTurn on RLS for every table in public, then add the smallest policy that makes your feature work. The Security Advisor in the dashboard flags tables that have RLS off.

Open the SQL Editor and run this to create a table where each user only sees their own notes:

SQL Editor
create table public.notes (
  id bigint generated always as identity primary key,
  user_id uuid not null default auth.uid() references auth.users on delete cascade,
  body text not null,
  created_at timestamptz not null default now()
);

alter table public.notes enable row level security;

create policy "Read own notes" on public.notes
  for select to authenticated
  using ( (select auth.uid()) = user_id );

create policy "Insert own notes" on public.notes
  for insert to authenticated
  with check ( (select auth.uid()) = user_id );

create policy "Update own notes" on public.notes
  for update to authenticated
  using ( (select auth.uid()) = user_id )
  with check ( (select auth.uid()) = user_id );

create policy "Delete own notes" on public.notes
  for delete to authenticated
  using ( (select auth.uid()) = user_id );

-- Policies filter by user_id, so index it
create index on public.notes (user_id);

Wrapping auth.uid() in (select ...) lets Postgres run it once per query instead of once per row, which matters as tables grow.

Public read, owner write

For content anyone can read, such as published posts, give anon a select policy and keep writes restricted:

SQL
create policy "Anyone can read posts" on public.posts
  for select to anon, authenticated
  using ( published = true );

Read and write data

TypeScript
// Read with filters, ordering and a limit
const { data, error } = await supabase
  .from('notes')
  .select('id, body, created_at')
  .order('created_at', { ascending: false })
  .limit(20)

// Insert and get the new row back
await supabase.from('notes').insert({ body: 'Hello' }).select().single()

// Update
await supabase.from('notes').update({ body: 'Edited' }).eq('id', 42)

// Delete
await supabase.from('notes').delete().eq('id', 42)

// Join a related table through a foreign key
await supabase.from('posts').select('title, author:profiles(username)')

Always check error. A query that returns an empty array with no error usually means an RLS policy filtered out the rows, not that the table is empty.

Authentication

Supabase Auth supports email and password, magic links, one-time codes, phone, OAuth providers such as Google and GitHub, and anonymous sign-ins. Users live in the auth.users table, and their id is what auth.uid() returns in your policies.

TypeScript
// Sign up. With email confirmation on, the user must click the link first.
await supabase.auth.signUp({ email, password })

// Sign in
await supabase.auth.signInWithPassword({ email, password })

// Passwordless magic link
await supabase.auth.signInWithOtp({ email, options: { emailRedirectTo: 'https://example.com/welcome' } })

// OAuth (configure the provider in Authentication, Providers first)
await supabase.auth.signInWithOAuth({ provider: 'github' })

// Current user, verified with the auth server
const { data: { user } } = await supabase.auth.getUser()

// React to sign in and sign out
supabase.auth.onAuthStateChange((event, session) => { /* update UI */ })

await supabase.auth.signOut()
On the server, trust getUser, not getSessionA session read from cookies can be tampered with. On the server, call getUser() (or getClaims()) to verify the token before you use the user id for anything that matters.

Redirect URLs and email

  • In Authentication, URL Configuration, set the Site URL to your production domain and add your local and preview URLs to the redirect allow list. Magic links and OAuth fail with a redirect error when this is missing.
  • The built-in email sender is rate limited and meant for testing. For real users, add your own SMTP provider (for example Resend) in Authentication, Emails.

File storage

Storage keeps files in buckets. Public buckets serve files from a plain URL. Private buckets need a signed URL or an authenticated request. Access is controlled with RLS policies on the storage.objects table.

  1. Create a bucketStorage, New bucket. Name it, for example, avatars, and decide whether it is public. You can also set a file size limit and allowed MIME types.
  2. Add policiesWithout policies, uploads from the browser are refused. The example below lets users write only inside a folder named after their user id.
  3. Upload and serveUse the client to upload, then get a public URL or a signed URL.
SQL
create policy "Users upload to own folder" on storage.objects
  for insert to authenticated
  with check (
    bucket_id = 'avatars'
    and (storage.foldername(name))[1] = (select auth.uid())::text
  );
TypeScript
const path = `${user.id}/avatar.png`
await supabase.storage.from('avatars').upload(path, file, { upsert: true })

// Public bucket
const { data } = supabase.storage.from('avatars').getPublicUrl(path)

// Private bucket: link valid for one hour
const { data: signed } = await supabase.storage.from('docs').createSignedUrl('report.pdf', 3600)

Realtime

Realtime has three features. Pick the one that matches what you are syncing.

FeatureUse it for
Postgres ChangesListening to inserts, updates and deletes on a table
BroadcastLow-latency messages between clients, such as cursors or typing indicators. Also the recommended way to fan out database changes at scale.
PresenceTracking who is online in a room

Postgres Changes only fire for tables in the supabase_realtime publication, and RLS still applies to what each subscriber receives:

SQL
alter publication supabase_realtime add table public.notes;
TypeScript
const channel = supabase
  .channel('notes-feed')
  .on('postgres_changes',
      { event: 'INSERT', schema: 'public', table: 'notes' },
      (payload) => console.log('new note', payload.new))
  .subscribe()

// Clean up when the component unmounts
supabase.removeChannel(channel)

Each change is checked against every subscriber's policies, so Postgres Changes slows down with many listeners. Past a few thousand concurrent subscribers on the same table, Supabase recommends Broadcast instead.

Edge Functions

Edge Functions are TypeScript functions that run on Deno, close to your users. They are a good fit for webhooks, calling third-party APIs with secret keys, and small backend jobs. The free plan includes 500,000 invocations a month.

Terminal
npx supabase init
npx supabase functions new hello
npx supabase functions serve          # run locally
npx supabase secrets set STRIPE_KEY=sk_test_xxx
npx supabase functions deploy hello
supabase/functions/hello/index.ts
Deno.serve(async (req) => {
  const { name } = await req.json()
  return new Response(JSON.stringify({ message: `Hello ${name}` }), {
    headers: { 'Content-Type': 'application/json' },
  })
})
TypeScript
// Call it from the client. The user's token is sent automatically.
const { data, error } = await supabase.functions.invoke('hello', { body: { name: 'Ada' } })

By default a function requires a valid JWT. For public webhooks, such as one from Telegram or Stripe, deploy with --no-verify-jwt and verify the sender's signature yourself.

Pausing and backups

Free projects pause after about a week with no activity. A paused project keeps its data, and you can restore it from the dashboard with one click for up to a year. Paused projects do not count toward the two-project limit.

  • Prevent the pause with a small scheduled request that actually reads from the database. The keep-alive guide has a ready-made GitHub Actions workflow.
  • Back up yourself. The free plan has no automatic backups. Run npx supabase db dump -f backup.sql on a schedule, or before any risky migration.

Troubleshooting

My query returns an empty array but the table has rows

RLS is filtering them out. Check that a select policy exists for the role making the request (anon or authenticated) and that the user is actually signed in when you expect them to be.

"new row violates row-level security policy"

Your insert or update is missing a policy, or the with check condition is false. The common cause is not sending user_id and not giving the column a default auth.uid().

Magic link or OAuth redirects to localhost in production

Set the Site URL and redirect URLs in Authentication, URL Configuration, and pass emailRedirectTo or redirectTo explicitly.

Sign-up emails stop arriving

The default email service has a low hourly limit. Configure custom SMTP for anything beyond testing.

Realtime subscription connects but no events arrive

The table is not in the supabase_realtime publication, or RLS blocks the subscriber from seeing the row.

Connection errors from a serverless function

Prefer the HTTP client (supabase-js) in serverless code. If you need a direct Postgres connection, use the pooler connection string from the Connect panel, not the direct one.

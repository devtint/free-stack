Cloudflare

Fast DNS, a free CDN in front of your site, serverless Workers and object storage with no egress fees. This guide shows how to set each one up and how to avoid the classic redirect loop.

What you get

Cloudflare's free plan covers four things most small projects need:

  • DNS for your domain, with a fast global network and a clean dashboard.
  • Proxy and CDN. Proxied records hide your origin, cache static files and add DDoS protection.
  • Workers, serverless functions that run in every Cloudflare location and can also serve static sites.
  • R2, S3-compatible object storage with no charge for downloads.

Move your DNS to Cloudflare

  1. Add your domainIn the dashboard, choose Add a domain and pick the Free plan. Cloudflare scans your existing records.
  2. Check the imported recordsCompare them with your current DNS provider. Scans miss things, especially mail records (MX, SPF, DKIM).
  3. Change the nameserversAt your registrar, replace the nameservers with the two Cloudflare shows you. Turn off DNSSEC at the registrar first if it is on.
  4. Wait for activationUsually under an hour, sometimes up to a day. Cloudflare emails you when the domain is active.

Cloudflare supports a CNAME on the apex domain (CNAME flattening), which many registrars do not.

Proxy and SSL modes

Each A, AAAA and CNAME record has a proxy toggle. Proxied (orange cloud) sends traffic through Cloudflare. DNS only (grey cloud) just answers the DNS query, and visitors connect to your host directly.

When a record is proxied, the SSL/TLS encryption mode controls how Cloudflare connects to your origin:

ModeVisitor to CloudflareCloudflare to originUse it?
FlexibleHTTPSHTTPAvoid. Causes redirect loops with hosts that force HTTPS.
FullHTTPSHTTPS, certificate not checkedOnly as a temporary step
Full (strict)HTTPSHTTPS, valid certificate requiredYes. Vercel, Render and most hosts have valid certificates.
"Too many redirects"This almost always means the mode is Flexible while your host redirects HTTP to HTTPS. Set SSL/TLS to Full (strict).

Using Cloudflare with Vercel and Render

Vercel

Vercel already runs its own CDN and issues certificates. Vercel recommends DNS only records. Proxying through Cloudflare adds a second CDN, can interfere with certificate renewal and hides real visitor IPs from Vercel's firewall.

  1. Add the domain in Vercel firstProject, Settings, Domains. Note the A and CNAME values it gives you.
  2. Create those records in CloudflareSet the proxy status to DNS only.
  3. Wait for the green check in VercelVercel then issues the certificate.

Render

  1. Add the custom domain in RenderService, Settings, Custom Domains.
  2. Create a CNAME in CloudflarePoint it at your-service.onrender.com. Start with DNS only so Render can verify the domain and issue its certificate.
  3. Optionally turn on the proxyOnce Render shows the certificate as issued, you can proxy the record. Set SSL/TLS to Full (strict).

Workers

A Worker is a JavaScript or TypeScript module with a fetch handler. It starts in milliseconds with no cold-start delay, which makes it great for small APIs, redirects, webhooks and edge logic.

Terminal
npm create cloudflare@latest -- my-worker   # pick "Hello World" and TypeScript
cd my-worker
npx wrangler dev        # local server on http://localhost:8787
npx wrangler deploy     # live on my-worker.your-subdomain.workers.dev
src/index.ts
export default {
  async fetch(request: Request, env: Env): Promise<Response> {
    const url = new URL(request.url)

    if (url.pathname === '/api/time') {
      return Response.json({ now: new Date().toISOString() })
    }
    return new Response('Not found', { status: 404 })
  },
}

Configuration lives in wrangler.jsonc. Variables go in vars, and secrets are set from the CLI so they never touch your repo:

wrangler.jsonc
{
  "name": "my-worker",
  "main": "src/index.ts",
  "compatibility_date": "2026-11-01",
  "vars": { "APP_ENV": "production" },
  "triggers": { "crons": ["*/30 * * * *"] }
}
Terminal
npx wrangler secret put API_TOKEN   # prompts for the value

Scheduled Workers

With a triggers.crons entry, add a scheduled handler. This is a reliable free alternative for jobs that run every few minutes, such as keep-alive pings.

TypeScript
export default {
  async scheduled(event: ScheduledController, env: Env, ctx: ExecutionContext) {
    ctx.waitUntil(fetch('https://my-api.onrender.com/healthz'))
  },
}

Static sites

Workers can serve a folder of static files alongside your code. Add "assets": { "directory": "./dist" } to wrangler.jsonc and run wrangler deploy. Requests for static files are free and do not count toward the daily request limit.

R2 object storage

R2 stores files like S3 does, but you never pay for downloads. It is a good home for user uploads, images and backups.

Terminal
npx wrangler r2 bucket create my-uploads
npx wrangler r2 object put my-uploads/hello.txt --file ./hello.txt

From a Worker

Bind the bucket in wrangler.jsonc, then use it through env:

wrangler.jsonc
{
  "r2_buckets": [{ "binding": "UPLOADS", "bucket_name": "my-uploads" }]
}
TypeScript
// Upload
await env.UPLOADS.put('avatars/42.png', request.body)

// Download
const obj = await env.UPLOADS.get('avatars/42.png')
if (!obj) return new Response('Not found', { status: 404 })
return new Response(obj.body, { headers: { 'Content-Type': 'image/png' } })

From Python or any S3 client

Create an API token in R2, Manage API tokens. You get an access key id and secret. The endpoint uses your account id, and the region is always auto.

r2.py
import os
import boto3

s3 = boto3.client(
    "s3",
    endpoint_url=f"https://{os.environ['R2_ACCOUNT_ID']}.r2.cloudflarestorage.com",
    aws_access_key_id=os.environ["R2_ACCESS_KEY_ID"],
    aws_secret_access_key=os.environ["R2_SECRET_ACCESS_KEY"],
    region_name="auto",
)

s3.upload_file("report.pdf", "my-uploads", "reports/report.pdf")

# Temporary download link, valid for one hour
url = s3.generate_presigned_url(
    "get_object", Params={"Bucket": "my-uploads", "Key": "reports/report.pdf"}, ExpiresIn=3600
)

To serve a bucket publicly, connect a custom domain to it in the bucket settings. The r2.dev public URL is rate limited and meant for development.

Troubleshooting

ERR_TOO_MANY_REDIRECTS

Set SSL/TLS mode to Full (strict). Flexible mode plus an HTTPS redirect on your host loops forever.

Custom domain stuck on "invalid configuration" in Vercel or Render

Turn the record to DNS only until the host verifies it and issues a certificate.

Worker returns error 1027

The account passed 100,000 requests for the day. It resets at midnight UTC. Serve static files as Worker assets so they do not count.

Worker fails with "exceeded CPU time limit"

The free plan allows 10 ms of CPU per request. Waiting on fetch does not count, but heavy parsing or crypto does. Move that work elsewhere or upgrade.

Email stopped working after moving DNS

The scan missed your MX or TXT records. Copy them from your old provider.

How Git thinks

Git tracks your project in three places. Most commands move changes from one to the next:

PlaceWhat it holdsMoved by
Working treeThe files on your disk, including unsaved experimentsYou, editing files
Staging areaThe exact changes that will go into the next commitgit add
RepositoryEvery commit, forever (until garbage collected)git commit

A remote, usually GitHub, is another copy of the repository. git push sends your commits there and git pull brings others' commits back.

First-time setup

git config --global user.name "Your Name"
git config --global user.email "you@example.com"
git config --global init.defaultBranch main
git config --global pull.rebase true     # keep history linear when pulling
git config --global core.editor "code --wait"

git config --list --show-origin          # see where each setting comes from

Use the email address attached to your GitHub account, or GitHub's private noreply address from Settings, Emails, so commits link to your profile.

SSH key for GitHub

  1. Create a key 
    ssh-keygen -t ed25519 -C "you@example.com"
    Press Enter to accept the default location, and set a passphrase.
  2. Add it to the agent 
    eval "$(ssh-agent -s)"
ssh-add ~/.ssh/id_ed25519
  3. Add the public key to GitHubCopy the contents of ~/.ssh/id_ed25519.pub into GitHub, Settings, SSH and GPG keys, New SSH key.
  4. Test it 
    ssh -T git@github.com
    You should see a greeting with your username.

The daily cycle

git status                 # what changed?
git diff                   # line by line, not yet staged
git add src/app.py         # stage one file
git add -p                 # stage piece by piece, interactively
git commit -m "Add login rate limit"
git push

git add -p is worth learning early. It shows each change and asks whether to stage it, so one commit holds one idea.

Start or join a project

# New project
git init
git add .
git commit -m "Initial commit"
git remote add origin git@github.com:you/project.git
git push -u origin main

# Existing project
git clone git@github.com:you/project.git

Write useful commit messages

  • Use the imperative mood: "Fix token refresh", not "Fixed" or "Fixes".
  • Keep the first line under about 70 characters. Add a blank line and a longer explanation if the why is not obvious.
  • Many teams use prefixes such as feat:, fix: and docs: (Conventional Commits), which tools can turn into changelogs.

Branches

A branch is a movable label pointing at a commit. Creating one is instant and costs nothing, so make one for every change.

git switch -c feature/search     # create and switch
git switch main                  # go back
git branch                       # list local branches
git branch -d feature/search     # delete after merging
git push -u origin feature/search

git switch and git restore replaced the overloaded git checkout for everyday use. checkout still works, but the new commands are harder to misuse.

Merge or rebase

MergeRebase
What it doesJoins two histories with a merge commitReplays your commits on top of another branch
HistoryTrue record of what happened, can look busyStraight line, easy to read
Safe on shared branchesYesOnly on branches no one else uses
# Merge main's latest work into your branch
git switch feature/search
git merge main

# Or rebase your branch onto main
git fetch origin
git rebase origin/main
# fix conflicts, then:
git add .
git rebase --continue
# after rebasing a branch you already pushed:
git push --force-with-lease
Prefer --force-with-leaseIt refuses to overwrite the remote if someone pushed commits you have not seen, where plain --force would silently delete them.

Resolve a conflict

  1. Open the fileGit marks the clash between <<<<<<<, ======= and >>>>>>>.
  2. Edit to the final versionKeep one side, the other, or a mix. Delete the markers.
  3. Mark it resolvedgit add the file, then git commit (for a merge) or git rebase --continue. To give up, use git merge --abort or git rebase --abort.

Undo and fix

Pick the command by where the mistake is:

SituationCommand
Discard edits to a filegit restore app.py
Unstage a file, keep the editsgit restore --staged app.py
Fix the last commit's message or add a forgotten filegit commit --amend
Undo the last commit, keep the changes stagedgit reset --soft HEAD~1
Undo the last commit and its changes completelygit reset --hard HEAD~1
Undo a commit that is already pushedgit revert <commit>
Copy one commit from another branchgit cherry-pick <commit>
Only rewrite unpushed historyamend and reset change existing commits. On a branch others have pulled, use revert, which adds a new commit that undoes the old one.

Stash: park work for later

git stash push -m "half-done search"   # save and clean the working tree
git stash list
git stash pop                          # bring the latest back
git stash push --include-untracked     # also stash new files

Reflog: find "lost" commits

Git records every place HEAD has pointed for about 90 days. After a bad reset or rebase, the old commit is almost always still there:

git reflog
# a1b2c3d HEAD@{2}: commit: Add search endpoint
git switch -c rescue a1b2c3d

Read the history

git log --oneline --graph --all     # compact picture of every branch
git log -p app.py                   # every change to one file
git log --since="2 weeks ago" --author="Ada"
git log -S "API_KEY"                # commits that added or removed this text
git show a1b2c3d                    # one commit in full
git diff main...feature/search      # what the branch adds
git blame -L 10,30 app.py           # who last changed lines 10 to 30

Already committed something you should not have?

git rm --cached .env      # stop tracking, keep the file on disk
echo ".env" >> .gitignore
git commit -m "Stop tracking .env"
A pushed secret is a leaked secretRemoving the file does not remove it from history, and bots scan GitHub within minutes. Rotate the key at the provider first, then clean up.

Troubleshooting

"Updates were rejected because the remote contains work that you do not have"

Someone pushed first. Run git pull (with pull.rebase true this rebases your commits on top), fix any conflicts, then push again.

"Permission denied (publickey)"

Your SSH key is not loaded or not added to GitHub. Run ssh-add -l to check, and ssh -T git@github.com to test.

I committed to main instead of a branch

Create the branch where you are, then move main back: git branch feature/x, git reset --hard origin/main, git switch feature/x. Only do this if you have not pushed main.

"detached HEAD"

You checked out a commit rather than a branch. If you made commits there, keep them with git switch -c new-branch.

How a bot works

A Telegram bot is a normal program that talks to Telegram's Bot API over HTTPS. Telegram delivers messages to your bot in one of two ways:

PollingWebhook
HowYour bot keeps asking Telegram for new updatesTelegram sends each update to your HTTPS URL
Needs a public URLNoYes, on port 443, 80, 88 or 8443
Best forLocal developmentProduction, and hosts that sleep when idle
On Render freeBreaks when the service sleepsWorks. An incoming update wakes the service.

You can only use one at a time. Setting a webhook disables polling, and polling fails while a webhook is set.

Create the bot with BotFather

  1. Open @BotFatherSearch for it in Telegram (check for the blue verified badge) and send /newbot.
  2. Choose a name and usernameThe name is what people see. The username must end in bot, for example notes_helper_bot.
  3. Save the tokenBotFather replies with a token like 123456789:AA.... Anyone with it controls your bot. Store it as an environment variable, never in code.
  4. Set the basicsUse /setdescription, /setabouttext and /setuserpic so the bot looks trustworthy.

Useful BotFather commands

CommandDoes
/mybotsManage existing bots and reach all settings
/setcommandsSet the menu of slash commands users see
/setprivacyIn groups, whether the bot sees all messages or only commands and mentions
/setjoingroupsAllow or block adding the bot to groups
/revokeIssue a new token and invalidate the old one. Do this immediately if the token leaks.

Your first bot, with polling

Terminal
python -m venv .venv
source .venv/bin/activate          # Windows: .venv\Scripts\activate
pip install "python-telegram-bot~=22.0"
export BOT_TOKEN="123456789:AA..."
bot.py
import logging
import os

from telegram import Update
from telegram.ext import Application, CommandHandler, ContextTypes, MessageHandler, filters

logging.basicConfig(level=logging.INFO)


async def start(update: Update, context: ContextTypes.DEFAULT_TYPE) -> None:
    name = update.effective_user.first_name
    await update.message.reply_text(f"Hi {name}. Send me any text and I will echo it.")


async def help_cmd(update: Update, context: ContextTypes.DEFAULT_TYPE) -> None:
    await update.message.reply_text("Commands: /start, /help")


async def echo(update: Update, context: ContextTypes.DEFAULT_TYPE) -> None:
    await update.message.reply_text(update.message.text)


def build_app() -> Application:
    app = Application.builder().token(os.environ["BOT_TOKEN"]).build()
    app.add_handler(CommandHandler("start", start))
    app.add_handler(CommandHandler("help", help_cmd))
    app.add_handler(MessageHandler(filters.TEXT & ~filters.COMMAND, echo))
    return app


if __name__ == "__main__":
    build_app().run_polling(allowed_updates=Update.ALL_TYPES)

Run python bot.py and message your bot. Everything in python-telegram-bot v20 and later is async, so handlers are async def and every API call is awaited.

Deploy as a webhook on Render

For production, run the bot inside a small FastAPI app. It receives updates on /telegram, exposes /healthz for uptime checks, and registers its own webhook on startup.

main.py
import os
import secrets
from contextlib import asynccontextmanager

from fastapi import FastAPI, HTTPException, Request, Response
from telegram import Update
from telegram.ext import Application, CommandHandler, MessageHandler, filters

from handlers import echo, help_cmd, start   # the functions from bot.py

TOKEN = os.environ["BOT_TOKEN"]
SECRET = os.environ["WEBHOOK_SECRET"]           # 1-256 chars: A-Z a-z 0-9 _ -
BASE_URL = os.environ["RENDER_EXTERNAL_URL"]    # set by Render automatically

ptb = Application.builder().token(TOKEN).updater(None).build()
ptb.add_handler(CommandHandler("start", start))
ptb.add_handler(CommandHandler("help", help_cmd))
ptb.add_handler(MessageHandler(filters.TEXT & ~filters.COMMAND, echo))


@asynccontextmanager
async def lifespan(_: FastAPI):
    await ptb.bot.set_webhook(
        url=f"{BASE_URL}/telegram",
        secret_token=SECRET,
        allowed_updates=Update.ALL_TYPES,
    )
    async with ptb:
        await ptb.start()
        yield
        await ptb.stop()


app = FastAPI(lifespan=lifespan)


@app.post("/telegram")
async def telegram_webhook(request: Request) -> Response:
    header = request.headers.get("X-Telegram-Bot-Api-Secret-Token", "")
    if not secrets.compare_digest(header, SECRET):
        raise HTTPException(status_code=403)
    update = Update.de_json(await request.json(), ptb.bot)
    await ptb.process_update(update)
    return Response(status_code=200)


@app.get("/healthz")
def healthz() -> dict:
    return {"ok": True}

  1. Create a Render web serviceConnect the repository. Build command pip install -r requirements.txt. Start command uvicorn main:app --host 0.0.0.0 --port $PORT.
  2. Add environment variablesBOT_TOKEN, a random WEBHOOK_SECRET (for example from python -c "import secrets; print(secrets.token_urlsafe(32))"), and your Supabase values.
  3. Set the health check pathUse /healthz.
  4. Deploy and testThe webhook registers on startup. Message the bot. The first reply after a sleep takes about a minute while Render wakes up.
  5. Keep it awake (optional)Point UptimeRobot at /healthz so replies are instant. See the keep-alive guide.
Telegram retries for youIf your service is asleep, Telegram holds the update and retries delivery, so messages are delayed, not lost. Pending updates are kept for up to 24 hours.

Check or reset the webhook by hand

Terminal
# Status, last error and pending update count
curl "https://api.telegram.org/bot$BOT_TOKEN/getWebhookInfo"

# Remove it (needed before using polling again)
curl "https://api.telegram.org/bot$BOT_TOKEN/deleteWebhook?drop_pending_updates=true"

Security

Verify every webhook request

Anyone who learns your webhook URL can post fake updates to it. The secret_token you pass to setWebhook is sent back in the X-Telegram-Bot-Api-Secret-Token header on every real request. Reject anything without it, using a constant-time comparison as in the example above.

Restrict admin commands

Python
ADMIN_IDS = {int(x) for x in os.environ.get("ADMIN_IDS", "").split(",") if x}

# Only these users can trigger /stats
ptb.add_handler(CommandHandler("stats", stats, filters=filters.User(user_id=ADMIN_IDS)))

Limit abuse per user

Python
import time

LAST_SEEN: dict[int, float] = {}

async def rate_limited(update: Update) -> bool:
    uid = update.effective_user.id
    now = time.monotonic()
    if now - LAST_SEEN.get(uid, 0) < 1.0:     # one request per second
        return True
    LAST_SEEN[uid] = now
    return False

This in-memory version resets when the service restarts. That is fine for basic spam protection. For strict quotas, store counters in your database.

Checklist

  • Token and secrets only in environment variables, with .env in .gitignore.
  • Validate and size-limit user input before saving it or passing it to another API.
  • When downloading user files, check the size first and never execute them.
  • Log errors, but never log the token or full update payloads with personal data.
  • Revoke the token with /revoke the moment you suspect a leak.

Store users in Supabase

Render's disk is wiped on restart, so keep state in Supabase. The bot runs on a server, so it uses the secret key.

SQL Editor
create table public.bot_users (
  telegram_id bigint primary key,
  username text,
  first_name text,
  language_code text,
  message_count int not null default 0,
  first_seen timestamptz not null default now(),
  last_seen timestamptz not null default now()
);

alter table public.bot_users enable row level security;
-- No policies: only the secret key (server side) can read or write.
db.py
import asyncio
import os
from datetime import datetime, timezone

from supabase import create_client

sb = create_client(os.environ["SUPABASE_URL"], os.environ["SUPABASE_SECRET_KEY"])


def _upsert(user) -> None:
    sb.table("bot_users").upsert({
        "telegram_id": user.id,
        "username": user.username,
        "first_name": user.first_name,
        "language_code": user.language_code,
        "last_seen": datetime.now(timezone.utc).isoformat(),
    }).execute()


async def track_user(user) -> None:
    # The client is synchronous, so run it off the event loop
    await asyncio.to_thread(_upsert, user)
Python
async def start(update, context):
    await track_user(update.effective_user)
    await update.message.reply_text("Welcome!")

Telegram's rate limits

Telegram throttles bots that send too fast and returns a 429 Too Many Requests error with a retry_after value.

WhereStay under
A single chatAbout 1 message per second
A group20 messages per minute
Broadcasts to many usersAbout 30 messages per second overall

For broadcasts, python-telegram-bot includes a rate limiter that queues messages for you:

Terminal
pip install "python-telegram-bot[rate-limiter]~=22.0"
Python
from telegram.ext import AIORateLimiter

app = Application.builder().token(TOKEN).rate_limiter(AIORateLimiter()).build()

Set the command menu from code

Python
from telegram import BotCommand

async def post_init(app: Application) -> None:
    await app.bot.set_my_commands([
        BotCommand("start", "Start the bot"),
        BotCommand("help", "How to use it"),
    ])

app = Application.builder().token(TOKEN).post_init(post_init).build()

Troubleshooting

"Conflict: terminated by other getUpdates request"

Two copies are polling with the same token, often your laptop and a server. Stop one. If a webhook is set, polling fails too, so call deleteWebhook first.

Webhook set, but the bot never replies

Run getWebhookInfo. The last_error_message field tells you whether Telegram got a 403 (secret mismatch), a 404 (wrong path) or a timeout.

Bot does not see messages in a group

Privacy mode is on by default, so the bot only sees commands and replies. Turn it off with /setprivacy, then remove and re-add the bot to the group.

First reply takes a minute

The Render service was asleep. Add an uptime monitor on /healthz, or accept the delay for low-traffic bots.
